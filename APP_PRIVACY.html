Приложение: «Смета ремонта» / Renovation Estimate Версия: 1.0.0 (сборка 1) Bundle ID: <ЗАМЕНИТЕ: com.apredator.renovationestimate> Итог анкеты: Data Not Collected («Данные не собираются»)

Документ описывает, какие ответы нужно дать в разделе App Store Connect → App Privacy для этого приложения, и почему. Ответы должны совпадать с опубликованной политикой конфиденциальности (PRIVACY_POLICY.md).

1. Главный ответ

В самом начале анкеты App Store Connect спрашивает, собирает ли приложение данные. Правильный ответ:

No, we do not collect data from this app

(Вариант формулировки в интерфейсе: «Data Not Collected».)

2. Сводка по трём итоговым блокам карточки App Store

Блок в карточке App StoreОтвет

Data Linked to You (данные, связанные с вами)None — таких данных нет

Ни один тип данных не отмечается как собираемый, поэтому все три блока остаются пустыми. Это и есть корректный результат для приложения, которое не передаёт данные с устройства.

4. Почему локальные данные не считаются «сбором»

Apple определяет «сбор» (collection) как передачу данных с устройства в приложении или за его пределами таким образом, что к ним есть доступ дольше, чем нужно для обработки запроса, — то есть данные покидают устройство. Для этого приложения:

  • названия помещений и материалов, размеры, проёмы, расход, запас и цены хранятся только локально во встроенном хранилище WebView (localStorage) и никуда не передаются;
  • у приложения нет серверной части, аккаунтов и входа, поэтому связать данные с человеком невозможно даже теоретически;
  • приложение не выполняет сетевых запросов и не содержит рекламных, аналитических и сторонних SDK;
  • единственный путь данных с устройства — явное действие пользователя: экспорт списка покупок в CSV или сохранение резервной копии в JSON через системное меню iOS «Поделиться». Это передача по инициативе пользователя, а не сбор разработчиком.

Используемые нативные плагины Capacitor (@capacitor/share для системного меню «Поделиться», @capacitor/filesystem для записи файла сметы) не собирают данные, не содержат аналитики и не выполняют сетевых запросов — они только передают файл в системные механизмы iOS по действию пользователя. Поэтому они не меняют ответ «Data Not Collected».

Соответственно, декларация «Data Not Collected» точна и не противоречит политике конфиденциальности.

5. PrivacyInfo.xcprivacy и NSPrivacyTracking

Чтобы декларация была подкреплена технически, в iOS-проект (Xcode) стоит добавить файл манифеста конфиденциальности PrivacyInfo.xcprivacy в target приложения. Он должен отражать те же ответы: отслеживания нет, данные не собираются.

Ключевые значения:

  • NSPrivacyTracking = false — приложение не отслеживает пользователя.
  • NSPrivacyTrackingDomains = пустой массив — доменов для отслеживания нет.
  • NSPrivacyCollectedDataTypes = пустой массив — собираемых типов данных нет.
  • NSPrivacyAccessedAPITypes — только те API из списка Apple «required reason», которые реально используются в сборке (см. ниже).

Пример содержимого PrivacyInfo.xcprivacy (создаётся в Xcode: File → New → File → App Privacy; или добавляется вручную в target приложения):

<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
	<key>NSPrivacyTracking</key>
	<false/>
	<key>NSPrivacyTrackingDomains</key>
	<array/>
	<key>NSPrivacyCollectedDataTypes</key>
	<array/>
	<key>NSPrivacyAccessedAPITypes</key>
	<array>
		<dict>
			<key>NSPrivacyAccessedAPIType</key>
			<string>NSPrivacyAccessedAPICategoryUserDefaults</string>
			<key>NSPrivacyAccessedAPITypeReasons</key>
			<array>
				<string>CA92.1</string>
			</array>
		</dict>
	</array>
</dict>
</plist>

Пояснения к NSPrivacyAccessedAPITypes:

  • NSPrivacyAccessedAPICategoryUserDefaults / CA92.1 — чтение и запись пользовательских настроек, доступных только самому приложению. Это типовой случай для Capacitor-приложения: движок и плагины обращаются к UserDefaults в контейнере приложения. Значение CA92.1 означает «доступ к user defaults только для данных самого приложения».
  • NSPrivacyAccessedAPICategoryFileTimestamp / C617.1 — добавьте, если сборка обращается к временным меткам файлов внутри контейнера приложения (например, плагины работы с файлами).
  • NSPrivacyAccessedAPICategoryDiskSpace / E174.1 — добавьте, если сборка проверяет свободное место на диске, чтобы записать файл экспорта.
  • NSPrivacyAccessedAPICategorySystemBootTime / 35F9.1 — добавьте, если сборка измеряет время, прошедшее между событиями внутри приложения.

Не добавляйте категории «на всякий случай»: перечисляйте только те API, которые действительно присутствуют в бинарнике. Если Xcode при выгрузке покажет предупреждение о required-reason API, добавьте соответствующую категорию с указанным кодом причины.

6. Info.plist: разрешения не нужны

Приложение не запрашивает доступ ни к каким защищённым данным, поэтому в Info.plist не должно быть ключей вида:

NSCameraUsageDescription
NSPhotoLibraryUsageDescription
NSPhotoLibraryAddUsageDescription
NSMicrophoneUsageDescription
NSLocationWhenInUseUsageDescription
NSLocationAlwaysAndWhenInUseUsageDescription
NSContactsUsageDescription
NSCalendarsUsageDescription
NSRemindersUsageDescription
NSUserTrackingUsageDescription
NSHealthShareUsageDescription
NSHealthUpdateUsageDescription
NSBluetoothAlwaysUsageDescription
NSMotionUsageDescription
NSLocalNetworkUsageDescription

Отсутствие этих ключей — ожидаемое и правильное состояние: iOS не будет показывать пользователю запросы на доступ, а ревьюер не увидит лишних разрешений. Если Xcode или сторонний плагин добавит такой ключ автоматически, удалите его, если соответствующая функция приложению не нужна.

Единственный ключ, связанный с приватностью, который имеет смысл добавить в Info.plist, — декларация экспортного шифрования (см. RELEASE_CHECKLIST.md, раздел про export compliance):

ITSAppUsesNonExemptEncryption = NO

Он не относится к сбору данных и не влияет на ответы App Privacy.
