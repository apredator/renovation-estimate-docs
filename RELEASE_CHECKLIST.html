1. Нумерация версий и сборок

Правила Apple:

  • Version (CFBundleShortVersionString, в Xcode — MARKETING_VERSION) — версия для пользователя, до трёх чисел: 1.0.0. В App Store Connect она должна совпадать с версией, указанной в карточке приложения.
  • Build (CFBundleVersion, в Xcode — CURRENT_PROJECT_VERSION) — целое число, уникальное для каждой загруженной сборки одной версии: 1, 2, 3… Для нового релиза увеличивайте build; для новой пользовательской версии меняйте version и начинайте build заново с 1.
  • После отправки сборки на ревью номер build переиспользовать нельзя.

Проверить текущие значения:

cd ios/App && agvtool what-marketing-version && agvtool what-version

В проекте уже выставлены MARKETING_VERSION = 1.0.0 и CURRENT_PROJECT_VERSION = 1, поэтому менять ничего не нужно — достаточно убедиться. Если понадобится поднять версию:

cd ios/App && agvtool new-marketing-version 1.0.0
cd ios/App && agvtool new-version -all 1

Проверить результат в проекте:

cd ios/App && grep -n "MARKETING_VERSION\|CURRENT_PROJECT_VERSION" App.xcodeproj/project.pbxproj

Альтернатива без командной строки: Xcode → target App → вкладка General → поля Version и Build.

  • ☐Version = 1.0.0
  • ☐Build = 1
  • ☐Для следующей загрузки той же версии build увеличен (2, 3, …)

4. Приватность и Info.plist перед архивом

  • ☐Декларация экспортного шифрования уже выставлена в Info.plist (ITSAppUsesNonExemptEncryption = false), добавлять ничего не нужно — только проверить:
  plutil -p ios/App/App/Info.plist | grep -i ITSAppUsesNonExemptEncryption

Если ключ почему-то пропал, вернуть его так:

  plutil -insert ITSAppUsesNonExemptEncryption -bool NO ios/App/App/Info.plist
  • ☐Убедиться, что в Info.plist нет ключей NS*UsageDescription и NSUserTrackingUsageDescription (приложению не нужны разрешения):
  plutil -p ios/App/App/Info.plist | grep -E "NS(Camera|Photo|Microphone|Location|Contacts|Calendar|Reminders|UserTracking|Health|Bluetooth|Motion)"

Ожидаемый результат — пустой вывод.

  • ☐Про манифест приватности: собственного PrivacyInfo.xcprivacy у target приложения нет — и это нормально. Манифесты поставляются внутри фреймворков Capacitor.framework и Cordova.framework, которые лежат в бандле. Убедиться в этом можно по собранному приложению:

Ожидаемый вывод — пути вида Frameworks/Capacitor.framework/PrivacyInfo.xcprivacy и Frameworks/Cordova.framework/PrivacyInfo.xcprivacy.

  • ☐В этих манифестах NSPrivacyTracking = false, а NSPrivacyCollectedDataTypes и NSPrivacyTrackingDomains пусты; приложение не добавляет collecting-типов. Дополнительный свой манифест можно добавить (см. образец в APP_PRIVACY.md, раздел 5), но это не обязательно и не требуется для прохождения ревью.

5. Архив и загрузка в App Store Connect

5.1. Через Xcode (рекомендуемый путь)

  • ☐В Xcode выбрать схему App.
  • ☐В верхней панели выбрать устройство Any iOS Device (arm64) (симулятор не подходит для архива).
  • ☐Меню Product → Archive. Дождаться окончания.
  • ☐В открывшемся Organizer нажать Distribute App.
  • ☐Выбрать App Store Connect → Upload.
  • ☐Выбрать Automatically manage signing (или вручную указать distribution-профиль).
  • ☐Снять/оставить галочку Upload your app's symbols (рекомендуется оставить).
  • ☐Upload. Дождаться письма от Apple об успешной обработке (обычно 5–30 минут).

5.2. Через командную строку (альтернатива)

Создать архив (проект собирается через Swift Package Manager, поэтому используется -project, а не -workspace):

xcodebuild -project ios/App/App.xcodeproj -scheme App -configuration Release -destination 'generic/platform=iOS' -archivePath build/App.xcarchive archive

В песочнице или CI добавьте пути для артефактов и кеша SwiftPM:

xcodebuild -project ios/App/App.xcodeproj -scheme App -configuration Release -destination 'generic/platform=iOS' -archivePath build/App.xcarchive -derivedDataPath ios/DerivedData -clonedSourcePackagesDirPath ios/SpmCache archive

Проверить, что архив содержит нужную версию:

/usr/libexec/PlistBuddy -c "Print :ApplicationProperties:CFBundleShortVersionString" build/App.xcarchive/Info.plist
/usr/libexec/PlistBuddy -c "Print :ApplicationProperties:CFBundleVersion" build/App.xcarchive/Info.plist

Создать файл параметров экспорта ExportOptions.plist (для Xcode 15+ используется метод app-store-connect; в более старых Xcode — app-store):

cat > ExportOptions.plist <<'EOF'
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
    <key>method</key>
    <string>app-store-connect</string>
    <key>teamID</key>
    <string>5W2254G25J</string>
    <key>uploadSymbols</key>
    <true/>
    <key>compileBitcode</key>
    <false/>
    <key>manageAppVersionAndBuildNumber</key>
    <false/>
</dict>
</plist>
EOF

Выгрузить архив в App Store Connect:

xcodebuild -exportArchive -archivePath build/App.xcarchive -exportOptionsPlist ExportOptions.plist -exportPath build/export

Загрузка через altool с ключом App Store Connect API (если настроен ключ .p8):

xcrun altool --upload-app --type ios --file build/export/App.ipa --apiKey "<ЗАМЕНИТЕ: KEY ID>" --apiIssuer "<ЗАМЕНИТЕ: ISSUER ID>"

Альтернатива без командной строки: приложение Transporter из Mac App Store или Xcode → Organizer → Distribute App.

  • ☐Сборка появилась в App Store Connect → ваше приложение → TestFlight (или Builds) со статусом Processing → Ready to Submit.
  • ☐На почту пришло уведомление об обработке без предупреждений о приватности и required-reason API.

6. TestFlight: внутреннее тестирование

  • ☐В App Store Connect → TestFlight → Internal Testing создать группу, например Internal.
  • ☐Добавить тестировщиков (до 100 внутренних участников команды, аккаунты Apple ID).

  • ☐После одобрения установить TestFlight на iPhone и проверить по сценарию:
    • ☐создать 2–3 помещения, ввести длину/ширину/высоту;
    • ☐проверить, что данные сохраняются сами (закрыть и снова открыть приложение — правки на месте, кнопки «Сохранить» нет);
    • ☐добавить дверь и окно, проверить уменьшение площади стен;
    • ☐добавить покраску, обои, плитку, напольное покрытие и плинтус;
    • ☐изменить запас на подрезку и цену за упаковку, проверить число упаковок и стоимость;
    • ☐проверить общий бюджет проекта;
    • ☐проверить агрегированный список покупок;
    • ☐экспортировать CSV через «Поделиться» и открыть файл в Numbers или Excel: разделитель «;», русские буквы читаются, есть строка «Проект» с названием проекта, колонки «Материал / Количество, шт. / Упаковка / Стоимость, ₽» и строка «Итого»;
    • ☐в блоке «Данные проекта» нажать «Скачать резервную копию» и сохранить JSON;
    • ☐изменить смету, затем «Загрузить из файла» — проект должен вернуться к состоянию из копии;
    • ☐попробовать загрузить заведомо испорченный файл (не JSON) — ожидается сообщение об ошибке, данные не меняются;
    • ☐нажать «Удалить данные» и убедиться, что сначала спрашивают подтверждение, а после — смета пуста;
    • ☐проверить ограничения ввода: размер 100 м, запас 100 %, цена 10 000 000 ₽; дробное число вводится и через запятую;

    • ☐удалить приложение и установить снова — убедиться, что данные удалились (ожидаемое поведение);
    • ☐проверить тёмную тему оформления, крупный системный шрифт, поворот экрана;
    • ☐проверить, что внизу главного экрана видны версия 1.0.0, платформа и пометка про ориентировочный расчёт.
  • ☐Исправить найденные дефекты, поднять build до 2, повторить разделы 1–6.
  • ☐Проверить, что на устройстве нет падений: Xcode → Window → Devices and Simulators → View Device Logs; либо xcrun simctl spawn booted log stream при отладке на симуляторе.

8. Export Compliance: шифрование

Приложение не использует собственную криптографию, не реализует шифрование данных и не выполняет сетевых запросов; применяются только стандартные механизмы iOS и, при необходимости, стандартный HTTPS-стек операционной системы. Это exempt encryption.

  • ☐В Info.plist установлено ITSAppUsesNonExemptEncryption = NO (см. раздел 4).
  • ☐В App Store Connect на вопрос об экспортном шифровании выбрать вариант, соответствующий формулировке:
  App uses only exempt encryption

(либо «Does not use encryption / uses only exempt encryption» — в зависимости от текущей формулировки формы).

  • ☐Не выбирать варианты про собственные алгоритмы, VPN, шифрование файлов паролем пользователя или проприетарную криптографию — этого в приложении нет.
  • ☐Если форма всё же запросит документы, указать, что приложение не реализует неисключённое шифрование и не передаёт данные по сети.

14. Мониторинг после релиза

  • ☐Первая неделя: проверять страницу приложения и новые отзывы ежедневно; отвечать на отзывы вежливо и по делу.
