Как проверить скриншоты

# размеры, палитра и признак того, что интерфейс отрисовался
node scripts/verify-screenshot.mjs screenshots/ios-6.9-main.png

Скрипт печатает размер, среднюю яркость, долю тёмного фона, светлого текста и акцентного цвета и падает с ошибкой, если экран пустой или белый.

Как снять скриншоты заново

# 1. Собрать приложение и синхронизировать веб-часть
npm run ios:sync

# 2. Собрать для симулятора (подпись не нужна)
xcodebuild -project ios/App/App.xcodeproj -scheme App -sdk iphonesimulator \
  -configuration Debug -derivedDataPath "$PWD/ios/DerivedData" \
  -clonedSourcePackagesDirPath "$PWD/ios/SpmCache" \
  -destination 'generic/platform=iOS Simulator' CODE_SIGNING_ALLOWED=NO build

# 3. Установить и запустить на нужном устройстве
DEV=$(xcrun simctl list devices available | grep "iPhone 17 Pro Max" | grep -o "[0-9A-F-]\{36\}" | head -1)
xcrun simctl boot "$DEV"
xcrun simctl install "$DEV" ios/DerivedData/Build/Products/Debug-iphonesimulator/App.app
xcrun simctl launch "$DEV" com.apredator.renovationestimate

# 4. Снять экран (приложение должно быть на переднем плане)
sleep 15
xcrun simctl io "$DEV" screenshot screenshots/ios-6.9-main.png

Важные детали:

  • Первый запуск после установки может показать пустой тёмный экран (стартует WebView). Если скриншот вышел пустым — перезапустите приложение и подождите 10–15 секунд: xcrun simctl terminate "$DEV" com.apredator.renovationestimate && xcrun simctl launch ….
  • Экраны «Список покупок» и «Помещение» открываются нажатиями в симуляторе. Чтобы снять их без ручного тапа, можно временно поменять начальное состояние в src/App.tsx (useState<'estimate' | 'shopping'>('estimate') → 'shopping' для списка покупок; useState<string | null>(null) → useState<string | null>(() => project.rooms[0]?.id ?? null) для редактора помещения), затем выполнить npx vite build, скопировать dist в ios/DerivedData/Build/Products/Debug-iphonesimulator/App.app/public, установить приложение и снять экран. После съёмки обязательно верните код и выполните npm run ios:sync — иначе в сборку попадёт изменённое стартовое состояние.
  • Перед финальной отправкой имеет смысл переснять скриншоты с Release-сборки (-configuration Release) — так в кадр не попадут отладочные артефакты.
  • На скриншотах не должно быть того, чего в приложении нет: например, кнопки «Сохранить PDF» (в iOS-сборке она не показывается, потому что window.print() в WKWebView не работает).
