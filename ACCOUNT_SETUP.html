Этот файл — рабочая инструкция для владельца аккаунта. Шаги 0–3 достаточно пройти один раз. После каждого шага указано, как проверить результат: часть проверок можно запустить в терминале (и я могу их выполнить), часть — только в веб-интерфейсе Apple.

Обозначения: 🌐 — действие в браузере, 🖥 — действие в Xcode, ⌨️ — команда в терминале, ✅ — что должно получиться.

Шаг 0. Членство в Apple Developer Program

🌐 https://developer.apple.com/account → войти под своим Apple ID → Membership details.

✅ Должно быть: статус Active, роль Account Holder (или Admin/App Manager).

  • Если членства нет: Enroll ($99/год). Для индивидуального аккаунта активация обычно занимает от нескольких часов до 2 суток.
  • Ваш Team ID: 5W2254G25J — уже прописан в проекте (ios/App/App.xcodeproj/project.pbxproj, ключ DEVELOPMENT_TEAM), поэтому в командах его указывать не нужно. Если Team ID изменится, поправьте в двух местах: в проекте и запустите scripts/release-ios.sh заново.

⌨️ Проверка (когда войдёте в Xcode, шаг 2):

defaults read com.apple.dt.Xcode IDEProvisioningTeams 2>/dev/null

✅ Должны появиться Team ID и роль. Пустой вывод = Xcode ещё не знает про аккаунт.

Шаг 1. Принять соглашения

🌐 https://appstoreconnect.apple.com → Business (в некоторых аккаунтах — Agreements, Tax, and Banking).

✅ В разделе не должно быть плашек Action needed / Review Agreement. Для бесплатного приложения без покупок достаточно соглашения о бесплатных приложениях (Paid Apps Agreement и банковские реквизиты не нужны).

Пока соглашение не принято, загрузки отклоняются с ошибкой Program License Agreement has not been accepted.

Шаг 2. Войти в Xcode и выпустить сертификат распространения

🖥 Xcode → Settings (⌘,) → Accounts → «+» → Apple ID → войти (потребуется пароль и код 2FA).

Затем в том же окне: Manage Certificates… → «+» → Apple Distribution → Done. (Если появится предложение создать и Apple Development — соглашайтесь, лишним не будет.)

⌨️ Проверка:

security find-identity -v -p codesigning | grep -Ei "Apple Distribution|iPhone Distribution"

✅ Ожидаемая строка: "Apple Distribution: Имя Фамилия (XXXXXXXXXX)". Сейчас в связке есть только Apple Development: tsaranov@me.com — им подписать отправку в App Store нельзя, поэтому этот шаг обязателен.

Если сертификат не создаётся (например, лимит сертификатов исчерпан), можно пойти вторым путём: оставить автоматическое управление подписью, и Xcode создаст сертификат сам при первой сборке с -allowProvisioningUpdates — скрипт релиза уже передаёт этот флаг.

Шаг 3. Зарегистрировать Bundle ID

🌐 https://developer.apple.com/account → Certificates, Identifiers & Profiles → Identifiers → «+».

  • Тип: App IDs → App
  • Description: Смета ремонта
  • Bundle ID: Explicit, значение com.apredator.renovationestimate (если хотите другой — скажите, я поменяю его в capacitor.config.ts, project.pbxproj и документах)
  • Capabilities: ничего не включать — приложение не использует ни камеру, ни геолокацию, ни уведомления, ни покупки
  • Continue → Register

✅ Идентификатор появился в списке Identifiers.

Xcode умеет создавать идентификатор автоматически при первом архиве, но ручная регистрация надёжнее: сразу видно, что имя свободно.

Шаг 5. Ключ App Store Connect API (для загрузки без ручных действий)

🌐 https://appstoreconnect.apple.com → Users and Access → Integrations → App Store Connect API → Team Keys → «+».

  • Name: release-ios
  • Access: App Manager
  • Generate → скачать файл AuthKey_XXXXXXXXXX.p8 (скачивается один раз), записать Key ID и Issuer ID со страницы.

⌨️ Положить ключ на место:

mkdir -p ~/.appstoreconnect/private_keys
mv ~/Downloads/AuthKey_*.p8 ~/.appstoreconnect/private_keys/
ls ~/.appstoreconnect/private_keys/

✅ Файл на месте. Дальше загрузка идёт командой:

export ASC_KEY_ID=XXXXXXXXXX
export ASC_ISSUER_ID=xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx
scripts/release-ios.sh --upload

Без ключа тоже можно: скрипт тогда загрузит сборку через аккаунт Xcode (шаг 2), а вручную это делается через Product → Archive → Distribute App.

Шаг 6. Публичные URL: Support и Privacy Policy

Apple требует два живых адреса. Принято решение публиковать документы в отдельном публичном репозитории (renovation-estimate-docs), чтобы основной репозиторий приложения оставался приватным. Страницы собираются в статический HTML, Jekyll не нужен.

  1. Опубликовать документы (соберёт сайт в docs-site/, создаст локальный репозиторий и отправит его на GitHub):
scripts/publish-docs.sh --push
# если репозиторий называется иначе:
REPO_URL=https://github.com/<логин>/<имя>.git scripts/publish-docs.sh --push
  1. Один раз включить Pages: GitHub → репозиторий документов → Settings → Pages → Source: Deploy from a branch → main / (root).
  2. ⌨️ Проверить, что страницы открываются без входа в GitHub:
curl -sS -o /dev/null -w "%{http_code}\n" https://apredator.github.io/renovation-estimate-docs/SUPPORT.html
curl -sS -o /dev/null -w "%{http_code}\n" https://apredator.github.io/renovation-estimate-docs/PRIVACY_POLICY.html

✅ Оба ответа 200. Сейчас — 404, потому что репозиторий документов ещё не создан.

Проверить страницы локально, до публикации:

npm run docs:site
python3 -m http.server 8080 --directory docs-site
# открыть http://localhost:8080/PRIVACY_POLICY.html и http://localhost:8080/SUPPORT.html

Другие варианты хостинга (если понадобится): готовый каталог docs-site/ — это обычный статический сайт, его можно залить на Cloudflare Pages, Netlify, Vercel, S3 или свой домен. Локальный путь к своему хостингу: скажите адреса — я подставлю их во все документы и в поля карточки.

Шаг 7. Карточка приложения

Заполнить в App Store Connect, значения брать из docs/APP_STORE_LISTING.md:

  • название, подзаголовок, промо-текст, ключевые слова, описание (RU, при желании EN);
  • скриншоты: screenshots/ — iPhone 6,9″ (3 шт.) и iPad 13″ (3 шт.);
  • App Privacy → «Data Not Collected» (подробно в docs/APP_PRIVACY.md);
  • Age Rating → 4+;
  • Support URL и Privacy Policy URL (шаг 6);
  • Copyright: © 2025 <ваше имя или компания>;
  • контакт для ревью: имя, фамилия, телефон, e-mail.

Шаг 8. Загрузка и TestFlight

Team ID уже в проекте, поэтому команда короткая:

scripts/release-ios.sh --upload

Скрипт проверит окружение, прогонит npm run verify, соберёт архив, экспортирует .ipa и отправит сборку в App Store Connect. Дальше она появится в TestFlight (обработка 10–30 минут). Прогнать сценарий проверки: docs/RELEASE_CHECKLIST.md, раздел TestFlight.

Шаг 9. Отправка на ревью

  1. App Store Connect → приложение → вкладка App Store → выбрать сборку из TestFlight.
  2. Проверить, что все блоки «Обязательно» заполнены (метаданные, скриншоты, App Privacy, возрастной рейтинг, экспортное соответствие — ответ «App uses only exempt encryption»).
  3. В App Review Notes вставить обоснование из docs/APP_STORE_LISTING.md (раздел про Guideline 4.2 — почему приложение не является «просто сайтом»).
  4. Add for Review → Submit for Review. Ревью обычно 1–3 дня.

Про push

Из этой среды отправить коммиты не получилось: в связке ключей нет токена GitHub, а git push запрашивает логин (could not read Username for 'https://github.com'). Отправить можно любым из способов:

# из вашего терминала (спросит логин/токен или возьмёт его из Keychain)
cd <путь к репозиторию>
git push origin main
  • Personal Access Token: GitHub → Settings → Developer settings → Personal access tokens → Fine-grained token, права Contents: Read and write на этот репозиторий; при push введите его вместо пароля (логин — ваш GitHub-логин).
  • SSH: git remote set-url origin git@github.com:apredator/renovation-estimate.git (нужен ключ в GitHub → Settings → SSH and GPG keys).
  • GitHub Desktop / Xcode: открыть репозиторий и нажать Push.

Готовые к отправке коммиты:

docs: пакет для App Store, скриншоты и инструкция по публикации
feat(ios): добавить проект Capacitor iOS, иконки и инструменты релиза
feat: переработать расчёт, хранение и экспорт для нативной сборки
