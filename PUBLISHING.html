3. Быстрый путь: один скрипт

# 1. Войти в Xcode: Settings → Accounts → «+» → Apple ID (один раз)
# 2. Выпустить сертификат: Manage Certificates → «+» → Apple Distribution
# 3. Запустить (без загрузки — только архив и .ipa):
scripts/release-ios.sh
# 4. Когда всё устраивает — загрузить в App Store Connect:
scripts/release-ios.sh --upload

Team ID (5W2254G25J) уже прописан в ios/App/App.xcodeproj/project.pbxproj (DEVELOPMENT_TEAM), скрипт читает его оттуда — отдельно передавать не нужно.

Скрипт делает: проверку окружения → npm run verify → npm run build + cap sync ios → Release-архив → .ipa → при --upload загрузку. Полезные переменные: BUNDLE_ID, DERIVED_DATA, SPM_CACHE, ASC_KEY_ID, ASC_ISSUER_ID, ASC_KEY_PATH.

Неинтерактивная загрузка (для CI) использует ключ App Store Connect:

# App Store Connect → Users and Access → Integrations → App Store Connect API → «+»
# Роль: App Manager. Скачанный AuthKey_XXXXXX.p8 положить в ~/.appstoreconnect/private_keys/
export ASC_KEY_ID=XXXXXXXXXX
export ASC_ISSUER_ID=xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx
scripts/release-ios.sh --upload

Альтернатива без скрипта: Xcode → Product → Archive → Distribute App → App Store Connect → Upload, затем TestFlight.

4. Публичные URL (Support и Privacy Policy)

Документы публикуются в отдельном публичном репозитории (renovation-estimate-docs), чтобы основной репозиторий приложения оставался приватным. Из Markdown собирается статический HTML (Jekyll не нужен), поэтому хостинг работает где угодно.

  1. Собрать и отправить:
scripts/publish-docs.sh --push
# или, если репозиторий назван иначе:
REPO_URL=https://github.com/<логин>/<имя>.git scripts/publish-docs.sh --push
  1. Один раз включить Pages: репозиторий документов → Settings → Pages → Source: Deploy from a branch → main / (root).
  2. Адреса для карточки приложения:
https://apredator.github.io/renovation-estimate-docs/                   — оглавление документов
https://apredator.github.io/renovation-estimate-docs/PRIVACY_POLICY.html — Privacy Policy URL
https://apredator.github.io/renovation-estimate-docs/SUPPORT.html        — Support URL
  1. Проверить, что обе страницы открываются без входа в GitHub (Apple проверяет URL):
curl -sS -o /dev/null -w "%{http_code}\n" https://apredator.github.io/renovation-estimate-docs/SUPPORT.html
curl -sS -o /dev/null -w "%{http_code}\n" https://apredator.github.io/renovation-estimate-docs/PRIVACY_POLICY.html

Проверить локально до публикации:

npm run docs:site
python3 -m http.server 8080 --directory docs-site

Каталог docs-site/ — обычный статический сайт: его можно выложить и на Cloudflare Pages, Netlify, Vercel или свой домен, если GitHub Pages не подходят. Файл .nojekyll отключает обработку Jekyll, чтобы страницы отдавались ровно такими, как собраны.

5. Карточка приложения и отправка на ревью

  1. My Apps → «+» → New App: платформа iOS, имя «Смета ремонта» (запасной вариант «Смета ремонта: калькулятор»), основная локализация — русский, bundle id com.apredator.renovationestimate, SKU — например renovation-estimate-1.
  2. Вставить поля из docs/APP_STORE_LISTING.md (RU; при желании — блок en-US).
  3. Загрузить скриншоты из screenshots/ (iPhone 6,9″ — 3 шт., iPad 13″ — 3 шт.; подписи — в docs/SCREENSHOTS.md).
  4. Заполнить App Privacy по docs/APP_PRIVACY.md («Data Not Collected») и Age Rating → 4+.
  5. Указать Support URL и Privacy Policy URL из шага 4, copyright и контакт для ревью.
  6. Дождаться обработки загруженной сборки в TestFlight, проверить её по сценарию из docs/RELEASE_CHECKLIST.md (офлайн, CSV, резервная копия, удаление данных).
  7. Выбрать сборку в разделе «App Store» и нажать Submit for Review. В App Review Notes вставить обоснование из APP_STORE_LISTING.md (раздел про Guideline 4.2).

7. Что можно поручить мне

  • заполнить плейсхолдеры (имя владельца, support-почта, copyright) в docs/ и выставить финальные URL GitHub Pages;
  • внести правки в тексты карточки после первых замечаний ревью;
  • проверить и пересобрать сборку после любых изменений (npm run verify, архив);
  • подготовить заново скриншоты и разобрать письмо об отказе, если ревью не пройдёт с первого раза.

Загрузку и нажатие «Submit for Review» придётся сделать вам — это требует вашей учётной записи Apple.
